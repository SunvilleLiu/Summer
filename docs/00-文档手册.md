# 财税服务协作 SaaS 文档手册 v3.0

> 交付模式：商业化公有云 SaaS、瀑布开发、全范围一次生产上线  
> 交付方式：产品所有人（OWNER）主导，AI 编码工具执行

## 1. 卷结构

文档基线由六卷组成，分基座与领域两层：

| 卷 | 层 | 内容 |
|---|---|---|
| `00-文档手册.md` | 基座 | 卷结构、独立性规则、稳定标识约定、基线限制 |
| `01-术语与概念.md` | 基座 | 术语、概念模型、领域编码、全局不变量、通用职责冲突守卫 |
| `02-产品需求与页面.md` | 基座 | 产品愿景、范围、商业化、功能与非功能需求、信息架构与页面清单 |
| `03-交付治理与上线.md` | 基座 | 治理角色与放行模型、阶段与质量门、供应商管理、迁移切换、测试 UAT、风险与待决策 |
| `04-系统设计.md`（附件：权限审批种子 JSON） | 领域 | 业务与领域设计、状态机与计算、技术架构、数据模型、安全灾备、身份权限审批、API 事件错误码 |
| `05-商业计费.md` | 领域 | 计费业务规则、实体、状态机、计算、API、事件、权限、运营，全部计费事实自闭合 |

阅读顺序：基座四卷是全部工作的前提输入；领域卷各自建立在基座之上，彼此互不依赖。

## 2. 独立性规则

1. **卷间零引用。** 任何卷不得出现其他卷的文件名、编号或章节指向；也不得使用其他领域卷定义的稳定标识。卷内引用（"本卷《章节》"）不受限制。
2. **一个事实只有一个家。** 每条规则、数值、状态、权限、门条件只在一卷出现；在第二卷复述即基线缺陷，发现后删除复述、保留权威卷一份。
3. **基座词汇。** 基座卷定义的内容（术语、概念、领域编码、全局不变量、治理角色 OWNER/TAX-ADVISOR/AI-EXEC/MACHINE-CHECK、质量门名、需求与页面标识、测试与迁移标识）是全体卷的公共词汇，领域卷可直接使用，不构成引用。
4. **领域卷互相绝缘。** 领域卷之间不得互用对方的标识或事实；需要共用的内容一律上移基座（如全局不变量、领域编码已上移术语卷）。
5. **交付物清单豁免。** 交付治理卷作为流程基座，可按卷名列举各阶段交付物与基线对象；这是工作产品清单，不是数据引用。
6. **跨卷映射归仓库。** 需求—设计—页面—API—数据—测试之间的映射关系（原追踪矩阵）不再是文档，由代码仓库生成并机检的追踪制品承载，随 GATE-LLD 起回填真实引用。

## 3. 稳定标识约定

标识采用 `<PREFIX>-<SUBJECT>-NNN`，前缀：`BR`（业务规则）、`FR`（功能需求）、`NFR`（非功能需求）、`DEC`（决策）、`DOM`（领域）、`ENT`（实体）、`PAGE`（页面）、`API`、`EVT`（事件）、`STATE`（状态机）、`CALC`（计算）、`TEST`（测试）、`MIG`（迁移）、`INV`（不变量）、`SOD`（职责分离）、`RISK`（风险，连续编号 `RISK-NNN`）、`GATE`（质量门）。

主题码优先使用 `PLT/ORG/WSP/IAM/CRM/CTR/SVC/FIN/ACC/TAX/INT/COL/ENTP/CONN/RPT/BILL/AUD/MIG/SEC/OPS`，不得用同义缩写另建编号。标识只在定义它的卷内使用与解释（基座词汇除外）；发布后不得改变语义或复用；被替代时保留原 ID 并以 `supersededBy` 指向后继。

## 4. 基线限制

各卷内容未完成相应质量门与变更控制前不构成冻结开发输入；"推荐""应当"和"设计为"仅在放行后转化为冻结输入。任何卷不得把尚未取得的供应商能力、合规结论、容量实测、代码、DDL、测试或生产验证描述为已经完成。

本基线只交付设计和管理文档，不等同于可执行代码、数据库 DDL、OpenAPI 文件、事件 Schema、原型源文件、自动化测试、迁移程序或基础设施即代码；这些制品在对应瀑布阶段由正式仓库生成、版本化、机检，并回填仓库追踪制品。容量数字、供应商、法规口径、价格和上线日期未有放行输入前，保持待决策状态，不得由执行方自行补成事实。
