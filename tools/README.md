# 文档基线机检

`check_docs.py` 把 `docs/00-文档手册.md` 的独立性规则、稳定标识约定和基线限制
变成每次提交自动执行的检查，并统计需求覆盖率与可评审性指标。

```bash
python3 tools/check_docs.py            # 全部检查
python3 tools/check_docs.py --quiet    # 只输出失败项与总结
```

无外部依赖，Python 3.9+。`docs/`、`tools/check_docs.py` 或工作流本身变更时，
GitHub Actions 自动运行并把结果写入作业摘要。

## 检查项

| 检查 | 依据 | 级别 |
|---|---|---|
| 标识归属与卷间独立性 | 手册 1/4：非公共词汇的稳定标识只能出现在定义它的一卷 | ERROR |
| 旧引用清理 | 手册 1：不得出现其他卷的文件名、编号或章节指向 | ERROR |
| 卷内引用可解析 | 手册 1：`《》` 引用须带「本卷」且章节名可解析 | ERROR |
| 权限审批种子对齐 | 手册 7：种子是权限/角色/SoD/审批模板的唯一可机检目录 | ERROR |
| 章节编号树 | 层级连续、带章前缀、无重号、父节点齐全 | ERROR |
| 格式与合卷痕迹 | 重复句号、连续空行、相邻重复标题、表格列数 | ERROR |
| 需求覆盖率 | FR/NFR 被设计或测试卷引用的比例，棘轮防回退 | WARN + 棘轮 |
| 可评审性 | 超长表格单元格数量，棘轮防增长 | WARN + 棘轮 |

WARN 不阻断，但每次运行都可见；ERROR 使检查失败。

## 三类可调项

**`ALLOWED_CROSS_VOLUME`** —— 经裁定保留的跨卷标识。每项必须写明理由，以 WARN
形式持续可见。裁定改变时从此处移除，检查随即变为 ERROR。

**`KNOWN_GAPS`** —— 经裁定保留的编号断档。补号会掩盖内容迁移轨迹，或使标题与
稳定标识错位，因此这些断档是有意的。

**`BASELINE`** —— 棘轮基线。这些数字只允许向好的方向变化：需求覆盖只增不减，
超长单元格只减不增。改善后应同步调高/调低基线，锁住成果。

## 已知的两个洞

`FR 覆盖率 0/136` 不是检查器的缺陷，是基线的真实状态：手册第 6 条把需求—设计—
测试的映射交给「代码仓库生成的机检追踪制品」，而该制品尚未建立。在它建立之前，
没有任何东西能证明 136 条功能需求都有设计和测试覆盖。追踪制品落地后，此处应从
统计升级为带阈值的 ERROR。

`超长单元格 15 个（最长 831 字符）` 影响的是评审可行性。瀑布模式下人工评审是
代码之前唯一的质量闸，单个单元格塞进八九个子句会让逐条核对无法进行。

## 维护提醒

正则里的词边界不可省略：`FR-[A-Z]+-\d+` 会匹配 `NFR-SEC-001` 的尾部，导致
覆盖率被高估。`FR_RE` 与 `NFR_RE` 的 `\b` 是必需的。
